# Change Stack

[English](README.md) · **Русский**

`cstack` – локальный инструмент для ревью pull request. Он открывает изменения в браузере, разбивает их на логические слои в порядке чтения и объясняет каждый слой с помощью вашей OpenAI-совместимой модели. Код, анализ и состояние ревью хранятся в памяти на вашем компьютере и удаляются при завершении процесса.

## Возможности

- **Слои** – модель группирует изменённые строки в логические шаги, упорядоченные так, чтобы основа шла первой. Один файл может входить в несколько слоёв.
- **Группы и зависимости** – независимые части работы, ссылки «опирается на» и полноэкранная карта слоёв (`G`).
- **Заметки к частям** – крупные слои разбиты на части, над каждой частью в коде стоит однострочная заметка (`N` скрывает их).
- **Категории** – короткая метка у каждого слоя, например «Backend fix» или «UI change».
- **Весь файл сбоку** – если слой показывает часть файла, полный diff открывается в боковой панели с изменяемой шириной.
- **Инструменты чтения** – split/unified diff, поиск (`⌘/Ctrl K`), навигация с клавиатуры, соседний контекст, поиск символов, прогресс просмотренных файлов, четыре темы GitHub/GitLab.
- **Исходный diff и комментарии** – выделите строку или диапазон по номеру строки; после короткой паузы появится ссылка на GitHub/GitLab и возможность оставить комментарий.
- **Обсуждения ревью** – открытые треды видны прямо в diff, решённые свёрнуты. Можно ответить, закрыть или переоткрыть тред. Раздел Conversation в боковой панели показывает также общие и устаревшие обсуждения; обновление доступно вручную и автоматически раз в пять минут.

## Установка

На **macOS на Apple Silicon (arm64)** скопируйте и выполните эту команду, чтобы установить [последний релиз](https://github.com/Neat-Snap/change-stack/releases/latest). Bun и Node.js не нужны.

```sh
bash -o pipefail -c 'curl -fsSL https://raw.githubusercontent.com/Neat-Snap/change-stack/master/scripts/install.sh | sh' && export PATH="$HOME/.local/bin:$PATH" && cstack --version
```

Установщик скачивает релиз, проверяет контрольную сумму, устанавливает `cstack` в `~/.local/bin` и при необходимости добавляет этот каталог в настройки вашей оболочки.

Бинарник не подписан и не нотарифицирован. Если macOS блокирует запуск, разрешите его в **Системные настройки → Конфиденциальность и безопасность**.

## Использование

```sh
cstack                                  # пошаговая настройка, затем вставьте ссылку на ревью
cstack 'https://gitlab.example/group/project/-/merge_requests/123'
cstack --demo                           # пример ревью без обращения к сети
cstack --help                           # все параметры
```

При первом запуске CLI запросит Git-токен с правами чтения ревью и отправки комментариев, а также базовый URL, идентификатор модели и API-ключ. Не закрывайте терминал во время ревью; `Ctrl+C` останавливает локальный сервер.

Один токен используется для чтения и комментариев:

- **GitLab:** область `api`, уже выбранная в ссылке настройки. Отдельной области только для комментариев нет; `api` разрешает доступ к API в пределах прав вашего аккаунта.
- **GitHub:** fine-grained токен с **Contents: Read-only** и **Pull requests: Read and write**. Ссылка настройки подставляет эти права и владельца репозитория. Выберите нужные репозитории; организация может потребовать одобрение. Для ревью форков также нужен доступ на чтение к исходному репозиторию.

Если сохранён токен только для чтения, выполните `cstack '<ссылка-на-ревью>' --setup-git`: заменится только Git-токен, настройки модели сохранятся. Права существующего GitHub-токена можно изменить на GitHub.

Нажмите на номер строки или выделите диапазон по номерам строк, дождитесь меню и выберите **Comment**. Напишите текст в Markdown и нажмите **Post to GitLab/GitHub** или **⌘/Ctrl+Enter**. Комментарий сразу публикуется от вашего аккаунта с сохранённым токеном. **Posted · view** открывает результат. При ошибке текст остаётся в редакторе. Черновики не сохраняются после закрытия страницы.

Комментарии доступны в split/unified diff, слоях и панели полного файла. Перед отправкой проверяются новые коммиты и изменения базы; если ревью изменилось, откройте его заново через `cstack '<ссылка-на-ревью>'`. Диапазоны из разных блоков diff и строки расширенного контекста вне исходного diff недоступны. В деморежиме комментарии не отправляются.

Выберите **Conversation** рядом с **All changes**, чтобы прочитать всю переписку, отфильтровать открытые или решённые треды и начать общее обсуждение. Над каждым тредом diff виден фрагмент кода с выделенными строками комментария и ссылками на полный diff и слои, в которых они есть. Для устаревших тредов показывается исходный код, если его предоставляет сервис, либо ссылка на оригинальное ревью. Ответы и изменения статуса сразу сохраняются в GitLab/GitHub с тем же токеном. Общее обсуждение GitHub остаётся плоским списком комментариев к PR. Обновление переписки сохраняет текущий diff и черновики ответов; новые коммиты загружаются при повторном открытии ревью. Устаревшие треды остаются в Conversation.

Настройки и ключи хранятся в `~/.change-stack/` (открытым текстом, права `0600`). Чтобы удалить их, удалите этот каталог.

## Разработка

Нужен Bun 1.3.14.

```sh
bun install --frozen-lockfile
bun run demo          # запустить UI с примером данных
bun run typecheck && bun run test
bun run build         # dist/cstack для текущей платформы
bun run test:tls && bun run test:ui
bun run test:line-actions  # браузерные проверки с локальной отправкой-заглушкой
bun run preview:conversations  # публичный PR, пример слоёв и тредов без модели и токена
bun run test:conversations     # браузерные проверки с имитацией API обсуждений
```
